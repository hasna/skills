# Managed Claude hooks in copied settings

`planClaudeManagedHookProjection` from `@hasna/skills` and
`skills hook project-claude-settings --expected-target-sha256 <digest> --json`
provide the same read-only projection. The CLI reads exact target settings bytes
from stdin and uses the normal canonical Skills home, policy and discovery guard.
It does not install hooks or write configuration.

The result contains the target SHA-256, a source witness and replacements naming
only an event, group index, handler index, old command digest and new command.
Other settings, account metadata, hook contents and policy bytes are not returned.
The four maintained Claude events are covered, including the `PreToolUse` Skill
guard. Missing events and explicit empty arrays stay unchanged.

Ownership requires an exact invocation generated by the Skills command renderer.
The old executable must resolve to the same trusted package entrypoint and bytes
as the canonical managed command. Package files and command parents must pass
the existing file safety checks. Legacy aliases are accepted only with that
evidence; shell wrappers, additional arguments, mismatched events, lookalike
executables and duplicate managed handlers are refused. Unrelated handlers,
group order, matchers, timeouts and other settings remain the caller's originals.

On macOS, the executable, package manifest and both alias/resolved ancestor
chains also require descriptor-bound native ACL verification, including final
rechecks. Absent and deny-only ACLs are accepted; every allow entry or unknown
native result is refused, even when POSIX write bits are clear. This preserves
the standard home-directory deny-delete ACL without interpreting shell output.
The existing system-alias guard retains its stricter no-ACL requirement.

The configuration owner must hold its own supported writer lease, preserve and
read back the complete target, then replan immediately before changing anything.
Pass the prior `sourceSha256` as `expectedSourceSha256` (CLI
`--expected-source-sha256`), compare the full target bytes/digest and each command
preimage, and refuse stale writes. Apply only the listed command leaves, read back
the complete result, and run the owner's full admission checks. Releasing and
reacquiring a lease requires fresh validation. This projection grants no lock,
repair, history, floor, credential, or native-session authority.

The source witness binds canonical policy/settings and executable bytes; observed
changes during planning refuse. A later source change requires a new plan. This
is a read-only observation, not a transaction with an unmanaged native writer;
CAS alone does not exclude writers that ignore the owning lease.
